= Ammitto Japan sanctions and export control data

image:https://github.com/ammitto/data-jp/actions/workflows/propagate.yml/badge.svg["Propagate data changes", link="https://github.com/ammitto/data-jp/actions/workflows/propagate.yml"]

This repository maintains Japanese sanctions and export control data as YAML
for Ammitto in `sources/sanction-lists/`. It covers Ministry of Finance asset
freeze lists, Ministry of Economy, Trade and Industry end user lists, and
export prohibition lists for Russia, Belarus and third countries. Local
scripts help contributors download and convert the official source files.

== Source

* Ministry of Finance (MOF), economic sanctions lists (asset freeze): https://www.mof.go.jp/policy/international_policy/gaitame_kawase/gaitame/economic_sanctions/list.html
* Ministry of Economy, Trade and Industry (METI), Foreign User List: https://www.meti.go.jp/policy/anpo/law00.html
* METI, security export control (List concerning Measures for the Maintenance of Peace and Security of Japan): https://www.meti.go.jp/policy/anpo/index.html
* Export prohibitions set by the Ministry of Foreign Affairs (MOFA), as consolidated lists published by METI, for example Russia: https://www.meti.go.jp/policy/external_economy/trade_control/02_export/17_russia/list_russia_tokutei.pdf

Each file here records the page or file it was transcribed from
(`announcement.url`, `announcement.source_url`, or `source_url`).

== Contents

The data is in `sources/sanction-lists/`, one folder per list:

* `mof-asset-freeze/`: the MOF asset freeze lists, one folder per list (such as `02-taliban` or `29-russia-individuals`), each holding dated versions of the list, such as `20260306.yml`
* `foreign-user-list/`: METI's Foreign User List, such as `20250929.yml`
* `fefta-list/`: METI's List concerning Measures for the Maintenance of Peace and Security of Japan, `20250131.yml`
* `russia-export-prohibition/`, `belarus-export-prohibition/`, `third-country-export-prohibition/`: one file per announcement that added entities, named after its date, plus `_index.yml`, the consolidated list

`sources/legal-instruments/` holds the laws the lists rest on;
`sources/supporting/` holds identifiers for lists, publishing bodies and
document types; `schemas/` holds the schemas; `reference-docs/` holds copies
of the published files the data was transcribed from.

`processed/` holds only an `_index.yaml` that lists no files; it is not where the data is.

Most files have an `announcement` block (`title` in Japanese and English,
`publish_date`, `authority`, and the source URL) and a list of entities. The
three export prohibition `_index.yml` files have no `announcement` block, so
no `publish_date`; their `sanction_list` block carries the `source_url` of
the consolidated list instead. The entities sit under
`sanction_details.entities` for the asset freeze, Foreign User and
`fefta-list` files, and under a top level `entities` key for the export
prohibition files.

Each entity:

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `id` | string | Stable identifier, such as `jp.mof.taliban.2`; the same entity keeps it across dated versions (absent in `fefta-list`)
| `name` | map | Name in Japanese (`ja`) and/or English (`en`); Foreign User and `fefta-list` names are mostly English only, and a few Foreign User entries have no name
| `type` | string | `individual` or `organization`
| `aliases` | list or map | Other names
| `sanction_list` | string | Identifier of the list, such as `jp/mof-asset-freeze-taliban`
| `sanction_list_en` | string | Asset freeze files: the list name in English
| `effective_date` | string | Date the measure took effect, where given
| `measures` | list | Measures, in Japanese and English, with `type` codes: `asset_freeze`, `export_license_requirement` or `prohibit_export_dual_use_items`
| `reason` | list | Reason given, where published
| `country_code`, `country_name` | string, map | Country of the entity (Foreign User, `fefta-list`, and Russia and Belarus export prohibition files)
| `address` | string | Address
| `title`, `date_of_birth`, `place_of_birth`, `nationality`, `identification`, `remarks` | various | Asset freeze files: further details as published, mostly in Japanese
| `entry_number` | integer | Export prohibition files: position in the published list
| `source_file`, `source_url` | string | Foreign User entries: the file the entry was taken from
|===

== Harmonized field mapping

The https://github.com/ammitto/ammitto/blob/74491e856c1e68aea52c0cf0e34061d48429d359/lib/ammitto/cli/harmonize/jp_announcement_transform.rb[general announcement reader] flattens top-level `entities` or `sanction_details.entities` for the https://github.com/ammitto/ammitto/blob/74491e856c1e68aea52c0cf0e34061d48429d359/lib/ammitto/sources/jp/transformer.rb[JP transformer]. The separately available https://github.com/ammitto/ammitto/blob/74491e856c1e68aea52c0cf0e34061d48429d359/lib/ammitto/data/japan/meti/transformer.rb[METI transformer] accepts `Data::Japan::Meti::Entity` fields, explicitly labeled below.

Targets below use canonical Ruby fields. Entity classes are under
`Ammitto::Ontology::Entities`; `SanctionEntry`, `OfficialAnnouncement`,
`SanctionReason` and `SanctionPeriodModification` are under
`Ammitto::Ontology::Sanction`; other target classes are under
`Ammitto::Ontology::ValueObjects`. JSON-LD uses the serializer's wire keys:
`SourceReference.fetched_at`, for example, is published as `retrievedAt`.

[cols="2,3,4",options="header"]
|===
| Input field | Canonical target | Transformation

| Entity `id`, or announcement `authority`, list and `entry_number`/position
| `Entity.id`; `SanctionEntry.id`
| General path prefers a supplied ID; otherwise derives one from authority, list and `entry_number` or record position, then mints source-qualified IRIs.

| Entity `name.en`, `name.ja`
| `NameVariant.full_name`, `script`, `is_primary`
| General path selects English or Japanese as the primary text and also reads the Japanese variant.

| Entity `type`
| `PersonEntity` or `OrganizationEntity`
| General path normalizes individual/person to person; otherwise selects an organization.

| Entity `address`
| `OrganizationEntity.addresses` → `Address.street`
| General path wraps nonblank address values as street text for organizations.

| Entity `remarks`, `reason`
| `Entity.remarks`
| General path joins text from both fields; English text is preferred within bilingual note objects.

| METI model `id`
| `OrganizationEntity.id`; `SanctionEntry.id`
| Uses the final dot-separated ID segment as the source reference for IRI generation.

| METI model `name_en`, `name_ja`, `aliases`
| `NameVariant.full_name`, `script`, `is_primary`
| Keeps English/Japanese names and aliases; alias script is selected from the text.

| METI model `country_code`, `country_en`, `country_ja`
| `Address.country_iso_code`, `country`
| Builds a country address when a code and a country name are present.

| METI model `wmd_types`
| `OrganizationEntity.remarks`; `SanctionEntry.reason_details` → `SanctionReason.localized_descriptions`
| Expands WMD codes into descriptions and category `wmd_proliferation`; the METI path constructs `export_restriction` effects.

| METI model `list_date`
| `TemporalPeriod.listed_date`, `is_indefinite`
| Copies the listing date into an indefinite period.
|===

== Using the data

Clone or download this repository and run either example from its root
directory. The Python example requires PyYAML
(`python3 -m pip install PyYAML`).

For the MOF asset freeze lists, read only the newest file in each folder: the
dated files are versions of the same list.

Ruby:

[source,ruby]
----
require "yaml"

def entities(doc)
  doc.dig("sanction_details", "entities") || doc["entities"] || []
end

paths = Dir.glob("sources/sanction-lists/mof-asset-freeze/*/").map do |dir|
  Dir.glob("#{dir}*.yml").max
end
paths += Dir.glob("sources/sanction-lists/{foreign-user-list,fefta-list}/*.yml")
paths += Dir.glob("sources/sanction-lists/*-export-prohibition/_index.yml")

paths.sort.each do |path|
  doc = YAML.safe_load_file(path, aliases: true)
  entities(doc).each do |entity|
    name = entity["name"]["en"] || entity["name"]["ja"] || ""
    puts [entity["sanction_list"], entity["type"], name].join("\t")
  end
end
----

Python:

[source,python]
----
import glob
import os
import yaml

base = "sources/sanction-lists"
paths = [max(glob.glob(os.path.join(d, "*.yml"))) for d in glob.glob(f"{base}/mof-asset-freeze/*/")]
paths += glob.glob(f"{base}/foreign-user-list/*.yml") + glob.glob(f"{base}/fefta-list/*.yml")
paths += glob.glob(f"{base}/*-export-prohibition/_index.yml")

for path in sorted(paths):
    with open(path, encoding="utf-8") as f:
        doc = yaml.safe_load(f)
    for entity in (doc.get("sanction_details") or {}).get("entities") or doc.get("entities") or []:
        name = entity["name"].get("en") or entity["name"].get("ja") or ""
        print(entity["sanction_list"], entity["type"], name, sep="\t")
----

== Updates

This repository is maintained by hand. The
link:.github/workflows/propagate.yml[Propagate data changes workflow] runs when
data changes on `main` and asks for the published JSON-LD to be rebuilt. The
list maintenance scripts below run locally; the workflow does not run them.

== Maintaining the data

Use Ruby and Bundler to install the link:Gemfile[Gemfile] dependencies with
`bundle install`. Run the commands below from the repository root and review
the generated YAML against the published source. `NEW_FILE.xlsx` and
`YYYYMMDD` are placeholders for the downloaded filename and publication date.

[cols="1,3",options="header"]
|===
| List | Maintenance path

| Foreign User List
| Run `bundle exec ruby scripts/update_foreign_user_list.rb`. It downloads the
METI spreadsheet into `reference-docs/` and writes a dated YAML file in
`sources/sanction-lists/foreign-user-list/`.

| MOF asset freeze lists
| Run `bundle exec ruby scripts/download_mof_sanctions.rb reference-docs`, then
`bundle exec ruby scripts/parse_mof_sanctions.rb reference-docs/NEW_FILE.xlsx sources/sanction-lists/mof-asset-freeze YYYYMMDD`.
Pass the downloaded file explicitly: the parser's default names a dated
spreadsheet. It writes a dated YAML file under each MOF list folder.

| FEFTA list
| Convert the published PDF to an HTML table, joining rows split across pages,
and save it as `reference-docs/YYYYMMDD-jp-end-user-list.html`. Run
`bundle exec ruby scripts/convert_html_to_yaml.rb reference-docs/YYYYMMDD-jp-end-user-list.html sources/sanction-lists/fefta-list/YYYYMMDD.yml`.

| Russia, Belarus and third-country export prohibitions
| Save the published PDFs in `reference-docs/russia-sanctions/` and record their
source URLs in its `metadata.yml`. Keep the consolidated filenames
`list_russia_tokutei.pdf`, `list_belarus_tokutei.pdf` and
`list_daisangoku_tokutei.pdf`. Run
`bundle exec ruby scripts/parse_russia_sanctions_pdf.rb` to write the separate
`*-export-prohibition/` lists, including their `_index.yml` files and dated
announcements.
|===

The link:scripts/[scripts/] contain the list-specific conversion code;
link:lib/mof_sanctions/[lib/mof_sanctions/] contains the MOF parser.
`validate_yaml_structure.rb` is a specialized comparison of legal-instrument
examples, not a validator for the sanctions corpus.

Run `bundle exec ruby scripts/validate_sources.rb` to validate every announcement
and legal-instrument document, plus the document-type and organization
taxonomies, using the Ammitto gem's Japan schemas. The command exits unsuccessfully
when any document is invalid or a source directory is empty. Index files and the
supporting sanction-list catalog are metadata outside those four schema types.
Pull requests run the same check with the gem revision pinned in
`.github/validation.Gemfile`.
